## หมวด 1 · ภาพรวม

### Q1. ระบบนี้คืออะไร ทำอะไรได้บ้าง
Farmy Voice คือแดชบอร์ดฟาร์มหมูที่สั่งงานด้วยเสียงภาษาไทย มี 9 หน้า: หน้าแรก, กราฟข้อมูล (จาก lab), กราฟย้อนหลัง, พยากรณ์, เทียบแนวโน้ม, วัคซีน, โรงเรือน/หมูป่วย, ตั้งค่า, ทำอะไรได้บ้าง

ผู้ใช้กดไมค์แล้วพูด → ระบบโชว์ข้อความที่ฟังได้ → ส่งให้ AI ตอบพร้อมข้อมูลจริง → อ่านคำตอบออกเสียง
ถ้าเป็นคำสั่ง "เปิดหน้า…" จะเปิดหน้านั้นทันทีในเบราว์เซอร์ ไม่ผ่าน AI

### Q2. ใช้เทคโนโลยีอะไรบ้าง
| ส่วน | เทคโนโลยี |
|---|---|
| หน้าเว็บ | React 18 + Vite, Recharts (กราฟ), React Router |
| เสียง | Web Speech API (STT ของ Google ผ่านเบราว์เซอร์) + SpeechSynthesis (TTS) |
| เซิร์ฟเวอร์ | Python 3.12 + FastAPI + uvicorn, 38 endpoints ในไฟล์เดียว `backend/main.py` (~2,900 บรรทัด) |
| ฐานข้อมูล | Supabase (PostgreSQL คลาวด์) 7 ตาราง |
| AI | Gemini 3.6 Flash (หลัก), CPF AI (รอ URL), Ollama (local), rule-based (สำรอง) |
| แจ้งเตือน | LINE Messaging API + GitHub Actions cron |
| ข้อมูลภายนอก | lab.plotnexuslab.com REST API |
| โฮสต์ | เซิร์ฟเวอร์บริษัท (หลัก) + Render (สำรอง) |

## หมวด 2 · การไหลของข้อมูล

### Q3. พูด 1 ประโยค ข้อมูลวิ่งไปไหนบ้าง
```
ผู้ใช้พูด
  → เบราว์เซอร์แปลงเสียงเป็นข้อความ (Google STT, ~1 วิ)
  → เช็คก่อนว่าเป็นคำสั่งเปิดหน้าไหม (voiceNav.js — ถ้าใช่ จบตรงนี้)
  → POST /ask ไป fern.plotnexuslab.com:8000 พร้อม token
  → เซิร์ฟเวอร์ตรวจ token → อ่านคำถามว่าต้องใช้ข้อมูลอะไร
      - ถามอากาศ/หมู/วัคซีน → ดึงจาก Supabase
      - ถามดิน/เล้า R/แสลงพัน → ดึงจาก lab API (แคช 60 วิ)
      - ถาม "ย้อนหลัง 3 วัน" → ดึง series/summary จาก lab
  → ประกอบเป็น context ส่งให้ Gemini พร้อม system prompt
  → Gemini ตอบ (~2–4 วิ) → บันทึกลง ai_logs
  → ส่งกลับเบราว์เซอร์ → อ่านออกเสียง
```
รวมประมาณ 3–6 วินาทีต่อคำถาม

### Q4. ข้อมูลเซนเซอร์เข้ามาทางไหน
1. **Jetson ที่ฟาร์ม** รัน Node-RED → `POST /ingest` ทุกครั้งที่อ่านค่าได้ → เก็บลง `weather_readings` (และส่งสำเนาขึ้น lab ถ้าตั้ง `LAB_USER/LAB_PASSWORD`)
2. **lab.plotnexuslab.com** เราไม่เก็บ ดึงสดตอนถาม ผ่าน 6 endpoint: sources, measures, locations, latest, series, summary — คีย์ API อยู่ฝั่งเซิร์ฟเวอร์ หน้าเว็บไม่เห็นคีย์

### Q5. ข้อมูลเก็บไว้ที่ไหน
| ที่ | เก็บอะไร | หมายเหตุ |
|---|---|---|
| **Supabase (คลาวด์)** | ข้อมูลจริงทั้งหมด 7 ตาราง: `weather_readings`, `pig_health_log`, `vaccine_schedule`, `admin_users`, `line_users`, `line_messages`, `ai_logs` | กล่องพังข้อมูลไม่หาย |
| **lab.plotnexuslab.com** | ข้อมูลดิน/เล้าหมู/เสาอากาศ | อ่านอย่างเดียว แคชในหน่วยความจำ 1–60 นาที |
| **กล่องบริษัท `/home/dev/farmy/`** | โค้ด + `backend/.env` (คีย์ลับ) + `farmy.log` | ไม่มีฐานข้อมูลบนกล่อง |

### Q6. ทำไมต้องมีเซิร์ฟเวอร์กลาง หน้าเว็บคุยกับฐานข้อมูลตรงไม่ได้หรือ
ได้แต่ไม่ปลอดภัย — คีย์ Supabase, Gemini, lab, LINE จะหลุดไปอยู่ในเบราว์เซอร์ทุกคน เซิร์ฟเวอร์กลางเป็นตัวถือคีย์ทั้งหมด หน้าเว็บได้แค่ token ชั่วคราวของตัวเอง

## หมวด 3 · AI

### Q7. AI ตอบมั่วไหม เอาข้อมูลจากไหนมาตอบ
AI ไม่ได้เดา — ทุกคำถามเราส่ง "ข้อมูลจริง ณ ตอนนั้น" แนบไปด้วย (อุณหภูมิล่าสุด, จำนวนหมูป่วย, วัคซีนที่ใกล้ถึง, ค่าจาก lab) แล้วสั่งใน system prompt ว่าตอบจากข้อมูลที่ให้เท่านั้น ถ้าไม่มีข้อมูลให้บอกว่าไม่มี และให้ระบุชื่อจุดติดตั้งเสมอ
ทุกคำถาม-คำตอบบันทึกใน `ai_logs` ตรวจย้อนหลังได้

### Q8. ถ้า AI ล่มหรือโควตาหมด
มีลำดับสำรอง 4 ชั้น: **CPF → Gemini → Ollama → rule-based**
ชั้นสุดท้ายเป็นโค้ดตายตัว ตอบคำถามพื้นฐานได้ (อุณหภูมิ ความชื้น หมูป่วย วัคซีน) โดยไม่ใช้ AI เลย ระบบจึงไม่มีวันตอบไม่ได้ แค่คำตอบจะสั้นลง `/health` บอกได้ว่าตอนนี้ AI ตัวไหนใช้ได้

### Q9. CPF AI ใส่ยัง
ใส่คีย์แล้ว โค้ดเรียกแบบ OpenAI-compatible (`/chat/completions`) พร้อมใช้ **แต่ยังขาด URL endpoint** ค่าที่ใส่ไว้ตอนนี้ต่อไม่ติด (timeout) ระบบจึงข้ามไป Gemini อัตโนมัติ พอได้ URL จริง แก้ `CPF_API_BASE` ใน `.env` แล้วรีสตาร์ท ไม่ต้องแก้โค้ด

## หมวด 4 · ความปลอดภัย

### Q10. ใครเข้าใช้ได้บ้าง ป้องกันยังไง
- ต้องล็อกอิน token แบบ HMAC-signed อายุ 7 วัน
- รหัสผ่านเก็บแบบ PBKDF2 (แฮช+salt) ไม่มีใครอ่านรหัสจริงได้แม้แต่ admin
- ล็อกอินผิด 5 ครั้ง บล็อก 15 นาที
- สมัครเองได้แต่ต้องมี **รหัสเชิญ** (`SIGNUP_CODE`) ปิดได้ทันทีโดยลบค่าออก
- Endpoint ที่ไม่ต้องล็อกอินมีแค่: login, signup, health, LINE webhook, `/ingest` (Node-RED), `/cron/*` (ต้องมี `X-Cron-Key`)
- คีย์ลับทุกตัวอยู่ในไฟล์ `.env` บนเซิร์ฟเวอร์ ไม่อยู่ใน GitHub

### Q11. มีอะไรที่ยังเสี่ยงอยู่
- รหัส admin ยังเป็นค่าเริ่มต้นที่ตั้งตอนติดตั้ง — ควรเปลี่ยน
- คีย์ Gemini/LINE/lab/CPF เคยถูกส่งผ่านแชท — แนะนำหมุนคีย์ใหม่
- ไม่มี HTTPS ระหว่าง Node-RED กับกล่องถ้าใช้ LAN ตรง (ถ้าผ่านโดเมนมี HTTPS แล้ว)

## หมวด 5 · โฮสต์ & การดูแล

### Q12. รันอยู่ที่ไหน ตั้งค่ายังไง
**กล่องบริษัท** (หลัก) — `/home/dev/farmy/` เป็น Ubuntu container ไม่มี Docker/systemd
- รัน uvicorn ที่พอร์ต 8000 พอร์ตเดียว เสิร์ฟทั้ง API และหน้าเว็บ (build ไว้ใน `frontend/dist`)
- เปิดเองตอนกล่องรีสตาร์ทผ่าน `/home/dev/autostart.sh`
- อัปเดตด้วยคำสั่งเดียว: `curl -fsSL https://raw.githubusercontent.com/fern2548/voice-ai/main/deploy/box-install.sh | bash` (ดึงโค้ดใหม่ + build + รีสตาร์ท)

**Render** (สำรอง) — deploy อัตโนมัติทุกครั้งที่ push GitHub, หลับถ้าไม่มีคนใช้ 15 นาที

### Q13. ถ้ากล่องพัง / ไฟดับ / ต้องย้ายเครื่อง
- ข้อมูลไม่หาย (อยู่ Supabase คลาวด์)
- ลงใหม่บนเครื่องไหนก็ได้ด้วยสคริปต์บรรทัดเดียว ~5 นาที
- ถ้าอยากเลิกพึ่งคลาวด์ มีชุด Docker (`deploy/`) ครบ: Postgres + PostgREST + API + web + backup ทุกคืน 02:00 เก็บ 14 วัน
- ระหว่างกล่องพัง ใช้ Render แทนได้ทันที (URL ต่างกัน)

### Q14. ค่าใช้จ่ายเดือนละเท่าไหร่
ตอนนี้ **0 บาท**: Supabase free (500 MB), Render free, Gemini free tier, GitHub Actions free, กล่องบริษัท
ถ้าโต: Supabase Pro ~$25/เดือน, Gemini คิดตามการใช้ (คำถามละ < 0.01 บาท)

### Q15. แจ้งเตือนวัคซีนทำงานยังไง
GitHub Actions ตั้ง cron ทุกวัน 07:00 (เวลาไทย) → เรียก `POST /cron/vaccine-due-notify` พร้อม `X-Cron-Key` → เซิร์ฟเวอร์เช็ควัคซีนที่ถึงกำหนดใน 3 วัน → ถ้ามีส่ง LINE broadcast; ไม่มีก็เงียบ
บนหน้าเว็บมีแถบแจ้งเตือนแยกรายการ กดแล้วพาไปหน้าวัคซีนพร้อมไฮไลท์รายการนั้น

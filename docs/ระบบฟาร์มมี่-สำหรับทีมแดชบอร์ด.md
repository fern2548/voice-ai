# ระบบฟาร์มมี่ (Farmy Voice) — เอกสารสำหรับทีมแดชบอร์ด

จัดทำ 2026-09-29 · เอกสารนี้อธิบายว่าระบบหลังบ้านทำงานอย่างไร
และมีทางไหนบ้างที่จะเอาไปต่อกับแดชบอร์ดของทีมคุณ

---

## 1. ระบบนี้คืออะไร

ระบบจัดการฟาร์มสุกรที่สั่งงานด้วยเสียงภาษาไทยได้ ทำ 3 เรื่องหลัก

1. **รับและแสดงข้อมูลเซนเซอร์** — อุณหภูมิ ความชื้น ลม ฝน แสง จาก Node-RED พร้อมค่าพยากรณ์จากโมเดล LSTM
2. **บันทึกงานฟาร์ม** — สุขภาพสุกร วัคซีน ชุดหมู คลังวัคซีน งานประจำวัน และกระทู้ปรึกษาสัตวแพทย์
3. **เครื่องมือช่วยตัดสินใจ** — คำนวณอาหาร แนะนำคู่ผสมพันธุ์ ขั้นตอนทำความสะอาด เช็กลิสต์มาตรฐานฟาร์ม
   (ส่วนนี้คำนวณในเบราว์เซอร์ทั้งหมด ไม่ต้องพึ่งเซิร์ฟเวอร์)

## 3. เอาระบบไปใส่ในแดชบอร์ด — มี 3 ทาง

### ทางที่ 1 — เรียก API ตรง (แนะนำ)

แดชบอร์ดของคุณเรียก HTTP ไปที่เซิร์ฟเวอร์นี้แล้วเอา JSON ไปวาดเอง
เหมาะที่สุดถ้าอยากคุมหน้าตาเองทั้งหมด ดูรายการ API ได้ในข้อ 5

```
GET  https://<ที่อยู่เซิร์ฟเวอร์>/weather
GET  https://<ที่อยู่เซิร์ฟเวอร์>/vaccine-due?days=7
```

**สำคัญ** — ระบบล็อกไว้เกือบทั้งหมดโดยปริยาย คนนอกเรียกได้เฉพาะข้อมูลทั่วไป
(อากาศ · พยากรณ์ · เซนเซอร์) ส่วนข้อมูลในฟาร์มทุกอย่างต้องล็อกอินก่อน
รายละเอียดว่าใครเห็นอะไรได้บ้าง อยู่ในข้อ 5

**เรื่อง CORS** — เซิร์ฟเวอร์อ่านค่าจากตัวแปร `ALLOWED_ORIGINS`

- **ถ้าไม่ได้ตั้งค่านี้** จะเปิดให้เรียกจากทุกโดเมน (`*`) แดชบอร์ดของคุณเรียกได้ทันที
- **ถ้าตั้งไว้แล้ว** ต้องเพิ่มโดเมนของแดชบอร์ดเข้าไปด้วย คั่นด้วยจุลภาค ไม่งั้นเบราว์เซอร์จะบล็อก

```
ALLOWED_ORIGINS=https://farm.example.com,https://dashboard.example.com
```

ตรวจค่าปัจจุบันได้จาก `.env` ของเซิร์ฟเวอร์ที่รันอยู่

### ทางที่ 2 — ฝังหน้าเว็บด้วย iframe

เร็วที่สุด ใช้ได้ทันทีโดยไม่ต้องเขียนอะไรเพิ่ม เหมาะกับหน้าที่เนื้อหาเยอะอย่าง
อาการของโรค · อาหารสัตว์ · การผสมพันธุ์ · ทำความสะอาดโรงเรือน · เช็กลิสต์

```html
<iframe src="https://<ที่อยู่เว็บ>/checklist" style="width:100%;height:900px;border:0"></iframe>
```

ข้อเสียคือได้ธีมและเมนูของฟาร์มมี่ติดไปด้วย กลืนกับแดชบอร์ดของคุณยาก

### ทางที่ 3 — ยกหน้าไปทั้งชุด

หน้าเครื่องมือ 5 หน้า (อาหาร · ผสมพันธุ์ · โรค · ทำความสะอาด · เช็กลิสต์)
**ไม่เรียกเซิร์ฟเวอร์เลย** คำนวณในเบราว์เซอร์ล้วน ๆ ถ้าแดชบอร์ดเป็น React อยู่แล้ว
ก๊อปได้ทั้งโฟลเดอร์

```
frontend/src/data/{feed,breeding,diseases,biosecurity,checklist}.js   ← เนื้อหาและสูตรคำนวณ
frontend/src/pages/{Feed,Breeding,Diseases,Cleaning,Checklist}Page.jsx ← หน้าจอ
frontend/src/utils/feedMix.js                                        ← อัลกอริทึมผสมอาหาร
frontend/public/{breeds,diseases}/*.svg                              ← ภาพประกอบ (วาดเอง ลิขสิทธิ์เป็นของฟาร์ม)
```

ต้องยก CSS ที่เกี่ยวข้องจาก `frontend/src/styles.css` ไปด้วย (คลาสขึ้นต้นด้วย
`fd-` `bd-` `vg-` `cl-` `ck-` `pnav-`)

## 4. การยืนยันตัวตน

ระบบมี 4 แบบ ใช้คนละงาน

### แบบที่ 1 — ล็อกอินผู้ใช้ (ใช้บ่อยที่สุด)

```
POST /admin/login     { "username": "...", "password": "..." }
   → { "token": "<payload>.<ลายเซ็น>" }
```

เอา token ที่ได้ใส่ใน header ของทุกคำขอถัดไป

```
X-Admin-Token: <token>
```

token เป็นข้อความที่เซ็นด้วย HMAC และมีวันหมดอายุในตัว เซิร์ฟเวอร์ไม่ได้เก็บ session ไว้
(รีสตาร์ทแล้ว token เดิมยังใช้ได้ ตราบใดที่ `SESSION_SECRET` ไม่เปลี่ยน)

**ระดับสิทธิ์**

| ระดับ | ได้มายังไง | ทำอะไรได้ |
| --- | --- | --- |
| `guest` | ไม่ได้ล็อกอิน | อ่านข้อมูลสาธารณะ |
| `staff` | ล็อกอินแล้ว | บันทึกข้อมูลทุกอย่างในฟาร์ม |
| `admin` | ชื่ออยู่ใน `ADMIN_USERS` | จัดการบัญชีผู้ใช้เพิ่มเติม |

### แบบที่ 2 — เซนเซอร์ยิงข้อมูลเข้า

```
X-Ingest-Token: <INGEST_TOKEN>
```
ใช้กับ `POST /ingest` และ `POST /ingest-prediction` เท่านั้น

### แบบที่ 3 — ตัวตั้งเวลาภายนอก

```
X-Cron-Key: <CRON_KEY>
```
ใช้กับ `/cron/*` ซึ่งเป็นงานส่งแจ้งเตือนเข้า LINE ตามเวลา

### แบบที่ 4 — ลิงก์รายงานสาธารณะ

`/r/<PUBLIC_REPORT_KEY>/...` คีย์อยู่ในลิงก์เลย ใช้กับปุ่มในริชเมนู LINE
ถ้าลิงก์หลุด ให้เปลี่ยนค่า `PUBLIC_REPORT_KEY` แล้วรีสตาร์ท ลิงก์เก่าจะใช้ไม่ได้ทันที

## 5. ความปลอดภัยของข้อมูล — ใครเห็นอะไรได้บ้าง

หลักที่ระบบยึด: **ข้อมูลภายในฟาร์มเห็นได้เฉพาะคนใน CP ที่ล็อกอินแล้ว
ส่วนข้อมูลทั่วไปเปิดให้คนนอกดูและใช้งานได้**

### 5.1 ชั้นแรก — ประตูหน้า ล็อกไว้ก่อนทั้งหมด

ทุกคำขอที่เข้ามาต้องผ่านมิดเดิลแวร์ `_require_admin_login` ก่อนเสมอ
ไม่ว่าจะเรียกเส้นทางไหน ถ้าไม่เข้าเงื่อนไขที่อนุญาตไว้ จะถูกปฏิเสธด้วย **401** ทันที
โดยยังไม่แตะฐานข้อมูลเลย

นี่คือแนวคิด "ปิดไว้ก่อน เปิดเฉพาะที่ตั้งใจ" ไม่ใช่ "เปิดไว้ก่อน แล้วค่อยไล่ปิด"
เพิ่มเส้นทางใหม่โดยไม่ทำอะไรเลย = เส้นทางนั้นถูกล็อกอัตโนมัติ

### 5.2 ข้อมูลแบ่งเป็น 3 ชั้น

| ชั้น | ข้อมูลอะไร | ใครเห็นได้ |
| --- | --- | --- |
| **ข้อมูลทั่วไป** | อากาศปัจจุบัน · ประวัติอากาศ · ค่าพยากรณ์ · ค่าดิบจากเซนเซอร์ · ข้อมูลจากระบบ lab · ถาม-ตอบเรื่องอากาศและวิธีฉีดวัคซีน | คนนอก ไม่ต้องล็อกอิน |
| **ข้อมูลภายใน** | หมูป่วย · บันทึกวัคซีน · ชุดหมูและแผนวัคซีน · คลังวัคซีนและล็อต · งานฟาร์ม · กระทู้ปรึกษาสัตวแพทย์ · คลังความรู้ · รายงานฟาร์ม · ตั้งค่า | เฉพาะคนใน CP ที่ล็อกอิน |
| **จัดการระบบ** | สร้าง-ลบบัญชีผู้ใช้ · ให้สิทธิ์สัตวแพทย์ | ผู้ดูแล (ชื่ออยู่ใน `ADMIN_USERS`) |

### 5.3 รายการที่คนนอกเรียกได้ — มีเท่านี้เท่านั้น

อ่านได้อย่างเดียว (GET) และเป็นข้อมูลที่ไม่ผูกกับตัวสัตว์หรือการผลิต

| เส้นทาง | ข้อมูล |
| --- | --- |
| `/weather` | ค่าอากาศปัจจุบัน |
| `/history` | ประวัติค่าอากาศ |
| `/predict` | ค่าพยากรณ์ |
| `/stats` | ค่าสถิติอากาศ |
| `/readings-log` | ค่าดิบจากเซนเซอร์ |
| `/predictions-log` | ประวัติค่าพยากรณ์ |
| `/lab/*` | ข้อมูลเซนเซอร์จากระบบ lab ภายนอก |
| `/admin/whoami` | ถามว่าตอนนี้เป็นใคร (คนนอกจะได้คำตอบว่า guest) |
| `/health` | สถานะระบบ ไม่มีข้อมูลฟาร์ม |
| `/ask` | ถาม-ตอบ มีการกรองอีกชั้น ดูข้อ 5.4 |

**เส้นทางอื่นทั้งหมดที่เกี่ยวกับหมู วัคซีน งานฟาร์ม และรายงาน คนนอกเรียกไม่ได้**

### 5.4 ชั้นที่สอง — ผู้ช่วย AI กรองคำถามอีกชั้น

`/ask` เปิดให้คนนอกถามได้ แต่ตรวจเนื้อคำถามก่อนตอบ
ถ้าคำถามแตะข้อมูลภายใน หรือเป็นคำสั่งบันทึก/ส่ง LINE จะไม่ตอบ และขึ้นข้อความว่า

> ข้อมูลส่วนนี้เป็นข้อมูลภายในฟาร์มครับ ต้องเข้าสู่ระบบก่อนถึงจะดูหรือบันทึกได้

| คนนอกถามได้ | คนนอกถามไม่ได้ |
| --- | --- |
| สภาพอากาศ พยากรณ์ ค่าเซนเซอร์ | จำนวนหมูป่วย ข้อมูลรายโรงเรือน |
| วิธีฉีดวัคซีน | ประวัติการฉีดวัคซีนของฟาร์ม |
| ข้อมูลสายพันธุ์หมูทั่วไป | คำสั่งบันทึกข้อมูลทุกชนิด |
|  | คำสั่งส่งรายงานเข้า LINE |

### 5.5 ชั้นที่สาม — คีย์เฉพาะทางสำหรับเครื่องคุยกับเครื่อง

ช่องทางที่ไม่ใช่คนเรียก ใช้คีย์แยกคนละตัว ไม่ปนกับบัญชีผู้ใช้
ถ้าคีย์ใดหลุด เปลี่ยนเฉพาะตัวนั้นได้โดยไม่กระทบส่วนอื่น

| ช่องทาง | คีย์ | ใช้ทำอะไร |
| --- | --- | --- |
| `/ingest`, `/ingest-prediction` | `X-Ingest-Token` | เซนเซอร์และ Node-RED ส่งค่าเข้ามา |
| `/cron/*` | `X-Cron-Key` | ตัวตั้งเวลาภายนอกสั่งส่งแจ้งเตือน |
| `/farm-context` | `X-Context-Key` | ระบบ AI ตัวแยกมาขอข้อมูลประกอบการตอบ |
| `/r/<คีย์>/…` | คีย์อยู่ในลิงก์ | ปุ่มรายงานในริชเมนู LINE |
| `/line/webhook` | ลายเซ็นของ LINE | LINE เรียกเข้ามาเอง |

### 5.6 บัตรผ่านของคนใน CP

- ล็อกอินแล้วได้ token ที่เซ็นด้วย HMAC มี **อายุ 7 วัน** ในตัว
- เซิร์ฟเวอร์ไม่เก็บ session ไว้ รีสตาร์ทแล้ว token เดิมยังใช้ได้ ตราบใดที่ `SESSION_SECRET` ไม่เปลี่ยน
- รหัสผ่านเก็บเป็น hash + salt (PBKDF2) ไม่เคยเก็บเป็นข้อความธรรมดา
- ลิงก์ดาวน์โหลดรายงานใช้ token ชั่วคราว **อายุ 60 นาที**

### 5.7 ข้อที่ทีมแดชบอร์ดต้องระวัง

1. **ห้ามฝัง `X-Admin-Token` ไว้ในโค้ดฝั่งหน้าเว็บ** ใครกด View Source ก็เห็น
   ถ้าแดชบอร์ดต้องแสดงข้อมูลภายใน ให้เซิร์ฟเวอร์ของคุณเป็นคนถือ token แล้วส่งต่อข้อมูลให้หน้าเว็บ
2. **ห้ามเอา `SUPABASE_SERVICE_KEY` ไปไว้ฝั่งเบราว์เซอร์** คีย์นี้มีสิทธิ์เต็มกับฐานข้อมูล
   ข้ามระบบสิทธิ์ทั้งหมดได้ในคีย์เดียว
3. **ลิงก์ `/r/<คีย์>` ใครถือก็เปิดได้** ห้ามโพสต์ที่สาธารณะ ถ้าหลุดให้เปลี่ยน `PUBLIC_REPORT_KEY` แล้วรีสตาร์ท
4. **`ALLOWED_ORIGINS` ไม่ใช่ระบบความปลอดภัย** ต่อให้เปิดกว้าง คนนอกก็ยังเรียกข้อมูลภายในไม่ได้
   เพราะยังต้องมี token อยู่ดี CORS แค่คุมว่าเบราว์เซอร์โดเมนไหนเรียกได้

### 5.8 สิ่งที่ยังไม่มี และควรทำเพิ่มถ้าจะใช้งานจริงเป็นวงกว้าง

เขียนไว้ตรง ๆ เพื่อให้ประเมินความเสี่ยงได้ถูก

- **ยังไม่มี rate limit** ใครก็ยิงคำขอรัว ๆ ได้ ทั้งหน้าล็อกอินและ `/ask`
- **ยังไม่มีบันทึกการเข้าถึง (audit log)** ไม่รู้ว่าใครเปิดดูข้อมูลอะไรเมื่อไร รู้แค่ใครแก้ข้อมูล
- **การเพิกถอน token เก็บในหน่วยความจำ** กดออกจากระบบแล้ว token ถูกยกเลิกจริง
  แต่ถ้าเซิร์ฟเวอร์รีสตาร์ท รายการจะหาย token เดิมกลับมาใช้ได้จนกว่าจะครบ 7 วัน
- **การกรองคำถามใน `/ask` ใช้วิธีจับคำ** ถ้าถามอ้อมมาก ๆ อาจหลุดได้ ควรทดสอบเพิ่มก่อนเปิดให้คนนอกใช้จริง
- **ยังไม่ได้แยกสิทธิ์รายโรงเรือนหรือรายฟาร์ม** คนในที่ล็อกอินแล้วเห็นข้อมูลทุกโรงเรือนเท่ากันหมด

## 7. ฐานข้อมูล

| `pig_health_log` | บันทึกจำนวนหมูป่วย/หมูทั้งหมดรายวัน |
| `vaccine_log` | ประวัติการฉีดวัคซีนจริง — วันที่ ชนิด โรงเรือน คอก ล็อต ผู้ฉีด |

| `vaccine_products` | ข้อมูลวัคซีนที่ฟาร์มมี — ล็อต วันผลิต วันหมดอายุ ผู้ผลิต |

## 10. วิธีรันระบบ

ต้องมี Node.js 18 ขึ้นไป และ Python 3.11 ขึ้นไป

**เซิร์ฟเวอร์**
```bash
cd backend
python -m venv venv
venv/Scripts/activate
pip install -r requirements.txt
cp .env.example .env        # แล้วเติมค่าให้ครบ
uvicorn main:app --reload --port 8000
```

**หน้าเว็บ**
```bash
cd frontend
npm install
npm run dev                 # เปิด http://localhost:5173
```

ตอน dev หน้าเว็บจะส่งต่อคำขอ API ไปที่พอร์ต 8000 ให้เอง (ตั้งไว้ใน `vite.config.js`)

> **ข้อควรระวัง** — ถ้าเพิ่มกลุ่ม API ใหม่ ต้องไปเพิ่มชื่อใน `vite.config.js` ด้วย
> ไม่งั้นตอน dev จะเรียกไม่ถึง และถ้าตั้งชื่อ API ซ้ำกับเส้นทางของหน้าเว็บ
> จะชนกันจนเปิดหน้านั้นไม่ได้ (เคยเกิดกับ `/tasks` เลยต้องเปลี่ยนเป็น `/farm-tasks`)

**นำข้อมูลเข้า-ออก**
```bash
python deploy/backup-db.py --out <โฟลเดอร์>              # สำรอง
python deploy/backup-db.py --restore <โฟลเดอร์> --yes    # นำกลับเข้า
```

## 11. เรื่องที่ควรรู้ก่อนต่อระบบ

- **`SUPABASE_SERVICE_KEY` มีสิทธิ์เต็มกับฐานข้อมูล** ต้องอยู่ฝั่งเซิร์ฟเวอร์เท่านั้น
  ห้ามส่งไปถึงเบราว์เซอร์หรือใส่ในโค้ดหน้าเว็บเด็ดขาด
- **ยังไม่มี rate limit** ถ้าเปิดให้เรียกจากภายนอกวงกว้าง ควรมีตัวกันไว้ก่อน
- **เซิร์ฟเวอร์อยู่บนแพ็กเกจฟรีของ Render** จะหลับเองเมื่อไม่มีคนใช้ 15 นาที
  คำขอแรกหลังหลับใช้เวลา 30–60 วินาที หน้าเว็บจึงยิง `/health` ปลุกไว้ตั้งแต่เปิดหน้า
  ถ้าแดชบอร์ดของคุณเรียก API ควรทำแบบเดียวกัน หรือย้ายไปแพ็กเกจที่ไม่หลับ
- **ตาราง `vet_posts` และ `vet_comments` ยังไม่ถูกสร้างในฐานข้อมูลจริง** SQL อยู่ใน
  `backend/schema.sql` แล้วแต่ยังไม่ได้รัน หน้าคอมมูนิตี้สัตวแพทย์จึงยังใช้งานไม่ได้
- **ข้อมูลเซนเซอร์หยุดไหลตั้งแต่ 13 กรกฎาคม 2569** ตาราง `weather_readings` มี 199 แถว
  ถ้าจะต่อแดชบอร์ดกับข้อมูลสด ต้องตรวจฝั่ง Node-RED ก่อน
- **หน้าเครื่องมือ 5 หน้าเก็บสถานะไว้ในเบราว์เซอร์ผู้ใช้เท่านั้น** (localStorage)
  เช่น เช็กลิสต์ที่ติ๊กไว้ ยังไม่ได้บันทึกลงฐานข้อมูล ถ้าต้องการให้ตรวจย้อนหลังได้
  ต้องเพิ่มตารางและ API ส่วนนี้
